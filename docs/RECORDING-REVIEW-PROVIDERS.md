# 录音复核服务与混音费用

设置中的“会后录音复核”独立于实时转录引擎。默认仍为 AWS Transcribe，也可选择豆包录音文件识别 2.0；手动新建复核时可以临时更换服务。使用豆包实时转录的会议也可进行录音复核。自动模式在新会议开始时保存服务选择并保留音频，结束后等待用户对照和采用结果，再进行文字校对与纪要。

## 配置

- AWS Transcribe 保留原有 profile、区域、S3 桶、词汇表与独立音源处理方式。
- 豆包文件识别复用设置中的 API Key，密钥仅存入 macOS 钥匙串，与流式转录共用。文件模型资源为 `volc.seedasr.auc`，需要单独开通。
- 临时音频使用现有 AWS profile 和 AWS / S3 区域。桶单独配置，留空时复用全局词汇表的桶。
- “检查录音文件连接”只照会随机任务 ID，不创建识别任务或发送音频；检查通过说明查询连接可用，实际提交权限与下载链路仍需真实调用验证。
- 豆包文件识别默认启用分句时间戳、标点、说话人信息，关闭语义顺滑。中英模式使用 SSD 200；日语显式指定 `ja-JP`，使用默认说话人能力。英日混合仍需选择 AWS。
- 可从本地全局词条直传最多 5000 个热词，不要求先同步 AWS 词汇表。

## 混音与估价

豆包复核将实际存在的两路录音按会议时间对齐为单声道 WAV，使用 16 kHz、16-bit PCM。规划阶段读取本地文件的实际帧数与采样率，使用 `audioStart`（旧录音回退到缓存起点）定位，重叠音频时长只算一次。完全没有录音覆盖的暂停间隔拆成独立任务，保留原时间偏移，不为这些空白上传长静音。

持续音频超过 4 小时时拆分任务，每个混音文件保持在豆包 512 MB 限制以下。转换和混音使用固定大小缓冲，按切片处理原文件，不把整场音频载入内存；多段缓存按需打开读取，避免同时持有大量文件句柄。原始两路录音保留。

单价采用用户给定的 **人民币 0.80 元／音频小时**。例如两路各 60 分钟且完全重叠，混音后 60 分钟，估算 0.80 元。提交窗口及复核版本显示两路原始时长、混音时长、文件数和费用；自动模式录音过程中先按时间位置估算，结束后按实际文件校准。S3 存储、请求、流量及后续 AI 校对/纪要费用不包含在识别费内。

每个版本保存估算单价和混音计划，历史版本不会随全局选项改变。网络中断时“已提交或等待确认部分估算”可能包含未被服务端受理的部分，不是已结算账单。

## 上传、恢复与清理

音频上传到私有 S3 前缀 `meetingrecord/batch/<meeting>/<version>/<chunk>.wav`。提交前读取一个字节验证 GetObject 权限，再签发两小时有效的只读下载链接；链接实际寿命还受 AWS 临时凭证有效期限制。Key 与预签名链接不写入版本、导出或日志，不修改桶的公开权限、加密或生命周期策略。

流程为查询已有任务、准备混音、上传、准备下载链接、持久保存“正在提交”与任务 ID、调用提交接口、轮询、保存结果、清理 S3 临时音频。S3 上传/签名失败时仍属于未提交，可以在修复配置后继续。提交请求中断后先查询同一个任务 ID；如果状态未知或结果过期，不自动重提，用户需显式创建新版本以重新识别。

豆包结果保存到本地后才删除临时 S3 对象。该清理不代表删除豆包服务端数据，也不取消已提交的识别任务。“停止等待”只停止本地等待。清理失败保留重试入口；版本控制桶的旧对象版本仍受用户自己的生命周期策略管理。

## 复核与兼容

版本列表显示服务来源。混音结果按时间范围与所有相关实时音源对照，支持查看原文、人物标签、采用本版及恢复实时原文。只有完整且有正文的结果可以采用。实时原文、人工修改、历史复核版本及纪要保留，来源不同的说话人编号不自动合并。

旧设置和旧批量版本缺少服务字段时按 AWS Transcribe 读取。真实会议数据库中不保存密钥或临时签名 URL。

## 验证入口

```sh
bash scripts/test.sh
.build/debug/MeetingAIValidate --check-doubao-recording-credentials
.build/debug/MeetingAIValidate --check-doubao-recording PROFILE REGION BUCKET TEST_AUDIO_FILE
.build/debug/MeetingAIValidate --check-doubao-recording-config TEST_AUDIO_FILE
```

真实链路测试只接受不超过 60 秒的测试音频。最后一个命令读取已保存的 S3 配置，但不读取会议内容或修改会议数据库；使用独立临时目录和新任务 ID。真实测试会上传至 S3、调用豆包并产生用量，成功后清理本次资源；失败时保留打印出的 receipt.json 供排查和清理。

2026-09-19 本地验证：原全量 175 项测试通过（Core 65、Cloud 78、Audio 32），覆盖时长合并、暂停偏移、长音频拆分、混音采样、旧版本兼容、提交状态持久化和恢复时防重复提交。随后针对实际接口响应补充回归测试，13 项录音复核相关测试通过。修复后的应用编译通过，`dist/MeetingRecord-Review.app` 已更新、通过签名校验并重启，现有会议和失败版本正常保留。

真实接口会对不存在的任务返回 HTTP 200 / API 45000000，`X-Api-Message` 为 `[Client-side generic error] OperatorWrapper Process failed: cannot find task`。查询逻辑已识别这一措辞，不再把首次查询误报为权限失败；未知的 45000000 仍按错误处理，HTTP 401/403 也不会被放行。此前已提交或提交状态不明的任务即使查不到，仍不会自动重新提交。

完成钥匙串授权后的真实链路验证：使用已有 S3 配置上传 31.62175 秒合成测试音频，豆包返回 3 段转录，本地保存和 S3 临时对象清理均通过。测试未提交真实会议，也未修改会议数据库。此结果验证了文件模型的提交、下载、轮询和清理，不代表长会议或所有语言的识别质量评估。
