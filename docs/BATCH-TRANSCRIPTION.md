# 会后用录音重新转录

默认方式是“可选：会后手动触发”。在开始记录前开启本地音频缓存，结束后进入“录音复核”，点击“新建批量转录”。没有缓存的历史会议无法从文字还原录音。

设置 → 会后用录音重新转录 → 执行方式，可改成“默认：结束记录后自动执行”。此时新会议自动保留录音，结束后先提交批量转录，并等待用户复核，不直接运行自动 AI 纪要。开始面板可以为当前会议单独关闭自动重转录。设置变更不追溯到已开始或已结束的会议。

录音上传桶可单独指定；留空时复用全局词汇表的桶。桶需位于所选 Transcribe 区域。手动新建任务使用当前 AWS profile、区域、词汇表，以及会议识别语言；自动任务使用会议开始时保存的配置。继续任务使用该版本冻结的配置和任务名。

## 复核与采用

批量结果左侧显示相同音源、时间范围的实时原文和已有人工修改，右侧显示批量正文。两种接口分段方式不同，左侧同一句可能对应右侧多段；完整实时原文也可展开，核对批量版是否漏掉发言。

- “采用本版，稍后校对”将此版本设为后续人工编辑、AI 校对和纪要的输入。
- “采用本版并校对、生成纪要”先持久保存选择，再调用现有 AI 流程。
- 可以恢复使用实时转录，原有人工修改也会重新作为输入。
- 批量结果及实时结果分别进入 SQLite 不可变原文校验。人工修改按各自片段 ID 保存，不跨版本自动迁移。
- 切换输入会使之前的校对、纪要过时。历史版本、引用快照、导出和来源说明仍保留。
- 批量发言人编号与实时版独立；“人物”页可确认或合并人物。麦克风仍标为“我”。

## 音频与语言

按本地缓存分段逐个处理，会议应用与麦克风分别提交。暂停、恢复、静音产生的分段保留原时间偏移，不把静音区间压缩拼接。新版本保存首批实际音频的时间位置，旧录音沿用已有缓存开始时间，可能有设备启动等待造成的偏差。

缓存以有界缓冲转换为 16 kHz、16-bit、单声道 WAV，转换过程不整场加载到内存。原缓存保留。没有帧的缓存跳过；录音缺失会报错，不能把不完整任务标为可采用。单个缓存超过 AWS 的 4 小时上限暂不支持。

固定语言使用 `Settings.VocabularyName`；中英混合和英日混合使用 `IdentifyMultipleLanguages`、`LanguageOptions`（中英：zh-CN / en-US；英日：en-US / ja-JP）、`LanguageIdSettings` 里的对应语言词汇表。词汇表需 READY，版本保存名称快照。全局词汇表清理会保护被批量版本引用的资源。

批量不保证比实时准确，也无法恢复未采集到的声音。两次 ASR 的人物分离结果可能不同。当前并未宣称真实会议准确率提升。

## 用量、恢复与清理

批量转录产生额外 AWS Transcribe 用量，按提交的各路录音分别计算，另有 S3 存储和请求费用。输入及输出位于用户指定桶的 `meetingrecord/batch/<meeting>/<version>/<chunk>.*`，不更改桶权限或默认加密。

每个任务的名称及对象位置在上传前落盘。已存在的任务仅查询，已落盘的录音片段结果不重复提交；失败的 AWS 任务不会自动反复重试。轮询最多等待一小时，可点“继续任务”继续等待。应用重启不自动恢复云端操作。

结果落盘后，应用尝试删除该片段的 Transcribe 任务、S3 输入录音与输出 JSON。清理失败不丢弃本地结果，可在界面重试清理。失败或中断的任务保留云端资源供继续；“停止等待”和退出应用不能保证停止 AWS 已提交的任务及其计费。

手动清理仅作用于本版本登记的任务与对象。清理未完成的任务后再次继续可能重新上传并计费；正在运行的 AWS 任务可能无法立即删除。S3 版本控制桶的 DeleteObject 可能只新增删除标记，历史版本需按桶生命周期规则管理。

删除本地会议不会自动清理尚存的云端资源，请先使用“清理云端文件”。本地缓存随会议删除，暂无自动到期清理。

## 所需权限

- S3：桶的 `s3:GetBucketLocation`，本功能对象前缀的 `s3:PutObject`、`s3:GetObject`、`s3:DeleteObject`。
- Transcribe：`transcribe:StartTranscriptionJob`、`transcribe:GetTranscriptionJob`、`transcribe:DeleteTranscriptionJob`。
- 使用词汇表时还需 `transcribe:GetVocabulary`。
- 桶使用 SSE-KMS 时需相应 KMS 权限；本应用不修改这些策略。

## 验证

```sh
bash scripts/test.sh
# 使用不含会议信息的测试语音；会真实上传、计费并清理本次资源
MeetingAIValidate --check-batch-file PROFILE REGION BUCKET AUDIO_FILE
```

验证命令使用独立临时目录，不修改应用偏好或会议数据库。失败时留下 `receipt.json` 记录任务和对象位置，便于排查和清理；成功且云端清理完成后删除临时目录。

0.5.0 已用不含会议内容的合成英文语音，通过原生 Swift SDK 实际完成 S3 上传、StartTranscriptionJob、结果下载解析及任务、输入、输出清理。复核界面已验证明暗两种外观。自动化测试覆盖输入选择、原文保护、词汇表参数、录音转换、时间偏移、任务恢复、取消与清理顺序；这不代表真实会议准确率已完成对比评估。
