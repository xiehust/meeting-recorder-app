# 豆包 2.0 实时转录

设置 → 实时转录引擎选择“豆包流式语音识别 2.0”，填写 API Key 并点击“保存 API Key”。密钥保存在 macOS 钥匙串，不进入 UserDefaults、会议数据库、导出或模型输入。点击“保存并关闭”保存引擎选项。旧设置默认仍为 AWS Transcribe。

API Key 下方的“检查豆包凭证”优先检查当前输入，输入为空时读取已保存的 Key。检查使用新版 `X-Api-Key` 鉴权，等待流式 2.0 小时版资源的 WebSocket 握手成功后立即关闭，不发送配置帧或音频。检查可取消，握手最长等待 15 秒；更换 Key 后清除旧结果。检查通过说明握手和连接访问成功，不代表识别效果或全部识别参数已经验证。

连接失败时显示 HTTP、URLSession、WebSocket 状态码，以及格式合法的服务端 Log ID；不输出原始错误对象、完整请求头、Key 或音频。HTTP 403 表示鉴权或资源访问被拒绝，不能单凭此状态认定 Key 无效或某一项权限必然缺失。应核对新版 Key 及 `volc.seedasr.sauc.duration` 的服务开通和授权状态。

## 音源与费用

豆包默认使用单路混音：会议应用与麦克风分别采集，转换为 16 kHz、16-bit PCM，按采集时的主机时间戳对齐，以固定增益混成单声道，再通过一个 WebSocket 发送。缓冲约 350 ms，每个输出包约 200 ms。没有输入的时间段补零，麦克风静音只停止该路采集，不重建混音连接。关闭会议或暂停时先排空采集和混音尾帧，再发送结束包。

设置中也可选择双路独立识别，两路分别连接豆包，个人麦克风仍标为“我”。混音模式由模型返回人物编号，先显示 A/B 等标签，可在人物页编辑姓名为“我”；不根据麦克风活动猜测身份。暂停/恢复后建立新连接，人物编号不跨会话自动合并。

本地仍可独立保存两路录音。混音没有内置声学回声消除：建议使用耳机，外放和重叠说话可能降低识别效果。原始缓存与是否启用录音复核是独立选项。

按用户提供的 **约人民币 0.93 元／音频小时** 估算，使用成功发送的 PCM 字节数除以 32000 得到音频秒数。单路混音持续一小时约 0.93 元；两路均持续发送一小时约 1.86 元。费用跟随会议保存当时的单价和用量，小于一分钱的正数显示为“< ¥0.01”。这不是账单或扣款确认，也不含 AI 校对和纪要费用。

## 识别与后续处理

使用官方优化版双向流式接口 `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async`，资源 ID 为 `volc.seedasr.sauc.duration`。固定启用 `enable_nonstream=true`、分句时间戳和标点；会议音轨及混音启用 `enable_speaker_info=true`、`ssd_version="200"`，关闭语义顺滑。

第一遍文字仅在临时区域展示。只有 `definite=true` 的分句写入不可变原文；按会话和分句起始时间去重，矛盾的确定结果触发错误，不覆盖已有文字。分句时间戳映射回会议时间。收到最终协议包且没有未确认文字才正常结束。发送积压超过五秒会终止该路连接并标记缺口；发送结束包后最多等候约三十秒，超时不会把临时文字变成原文。

已兼容 ASR 2.0 的 `utterances[].additions.speaker_id`，并保留旧 `speaker` 字段兼容。服务省略首句零起点时按零处理，后续不相关分句缺失起点仍拒绝；同时支持数字形式的字符串时间戳，继续拒绝 null、布尔值、倒序和非有限时间。显式验证命令在缺少说话人信息时可输出字段名称/类型诊断，不输出字段值、转录正文或凭证。

豆包二遍模式统一使用默认中英模型。界面允许中文、英文和中英混合偏好，日语/英日混合需选择 AWS。全局词汇表可作为豆包热词直接传入，无需 AWS 同步；针对文档的流式 100-token 上限，首版按 80 UTF-8 字节保守选取，开始面板显示实际选中的数量。模型权限与热词效果需要用真实请求验证。

实时转录与录音复核现为独立选择，豆包会议也可以复核录音。未开启自动复核时，结束后按既有自动 AI 设置进入文字校对及纪要；开启时先等待复核结果被采用。复核支持 AWS Transcribe 与豆包录音文件识别 2.0，详见 [录音复核服务](RECORDING-REVIEW-PROVIDERS.md)。每场会议保存自己的配置，全局切换不改动历史版本。

## 验证

`bash scripts/test.sh` 检查协议帧、压缩响应、临时/确定分句、重复结果、连接数量、费用、积压、收尾超时、混音对齐、静音和原有 AWS 行为。模拟服务响应不证明真实识别准确率。

在设置中保存 API Key 后，可以显式执行下列真实调用验证：

```sh
.build/debug/MeetingAIValidate --check-doubao-file /absolute/path/to/test-audio.wav
```

只检查凭证、无需音频文件时使用 `.build/debug/MeetingAIValidate --check-doubao-credentials`，同样读取钥匙串，不把 Key 放在命令行。

只接受不超过 60 秒的测试音频，发送至豆包并产生用量；使用钥匙串中的 Key，不把 Key 放进命令行，不读写会议数据库。验证确定文本及说话人信息，失败时不会输出音频、文本或密钥。该探测检验单条识别连接，混音与设备采集由单独的测试和实际会议验证。

参考：[流式 API 文档](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelstreamingautomaticspeechrecognitionAPI?lang=zh)。
