# 录音导入与会议问答

## 导入录音

侧栏选择 **导入录音**，或使用 **⌘I**。选择本机音频文件，填写会议标题、实际录音开始时间和识别语言。

- 支持系统音频解码器可读取的 M4A、MP3、WAV、CAF、AIFF，单文件最长 4 小时。
- 默认导入后上传转录，使用当前设置的 AWS Transcribe 或豆包录音文件识别服务。可选择是否使用全局词汇表，并填写本次 S3 桶。
- 关闭“导入后立即上传并转录”可仅保存到本地，稍后在“录音复核”中提交。
- 转录结束后查看结果，点击“采用本版，稍后校对”或“采用本版并校对、生成纪要”。转录、人物管理、人工修改、校对、纪要模板和导出沿用现有流程。
- 导入会议的“原文”页显示采用版本的识别原文；尚未采用时显示首个完整版本。人工修改不覆盖识别原文。已有实时会议仍保留实时原文。

导入只读取用户原文件，以固定大小缓冲区转换为 16 kHz 单声道 CAF，保存到 `Audio/<meeting UUID>/imported.caf`。原文件不会被移动或删除。导入失败或取消时删除本次尚未保存的临时副本。元数据存入现有 SQLite 会议记录。

应用内副本遵循现有录音缓存设置，自动保留期从**导入时间**计算。导入期间暂停缓存清理；转录任务运行期间继续保护录音。云端任务失败或被中断时，复用现有的继续任务、清理云端文件入口。已导入的本地录音和保存的转录保留。

## 会议问答

打开一场会议的 **问答** 页，可以连续提问、停止回答、重试失败的问题或清空该会议的对话。**⌘Return** 发送问题。

可选择三个资料范围：

- **原文与纪要**：当前采用转录的识别原文、人工修订及已接受的校对、最新纪要。
- **原始记录**：当前采用转录的识别原文，不含人工修改与纪要。
- **仅纪要**：最新纪要，包括手动编辑后的纪要正文。

问答使用本会议的纪要模型、连接和凭证，兼容已有 Bedrock Runtime 与第三方 Responses API 配置。提交时发送所选资料以及最近 12 轮成功对话；失败或取消的回答不进入历史。历史只用于理解追问，每次回答仍需以当前资料为依据。不会搜索其他会议。

回答显示来源编号、引用原句和模型名称。点击引用可查看提问时的完整来源片段，并定位对应转录。即使之后修改了转录或纪要，保存的引用快照仍可查看。资料变化或纪要已经过旧时显示提示。

问题、回答和纪要引用详情支持 GitHub Flavored Markdown，包括标题、粗体、斜体、删除线、行内代码、引用、嵌套列表、任务列表、表格和链接。识别原文和修订原文的引用详情仍按原文显示。

围栏代码块显示语言标签，支持 Swift、Python、JavaScript、TypeScript、JSON、Bash、SQL、YAML 等语言的语法高亮，并随界面深浅色切换。点击“复制代码”可复制代码正文，保留缩进和特殊字符。长代码行和宽表格可以横向滚动。无语言标签、不支持的语言或超过 64 KB 的代码块完整显示为等宽纯文本；不会删减内容。

渲染和高亮均在本地完成，不改变已保存的消息或引用。图片显示占位符，不自动请求远程图片；HTTP、HTTPS 和邮件链接仅在用户点击时打开，文件和脚本等其他链接不会启动。

模型返回 JSON 后，应用检查引用是否属于本次来源、引文是否为来源的连续原句、正文引用编号是否有效。验证失败不会保存为有效回答，也不会自动再次调用模型。资料不足时显示固定提示。这些检查能验证引用的出处，不能代替用户对回答含义的判断。

当前限制：单次问题最多 4000 字；包含历史的 JSON 输入最多 600,000 字节，超过时提示选择“仅纪要”或清空对话；不静默截断会议资料。回答采用完整响应模式，有处理状态与取消入口，不逐字流式显示。录音或其他处理进行时不能同时向该会议提问。

聊天记录和引用保存在对应会议中，重启后保留；未完成的回答标为中断，可手动重试。旧会议没有新字段也可正常读取。清空对话不改变转录、纪要或会议版本号。
