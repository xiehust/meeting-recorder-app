# 中日英多语言 · 0.6.1

设置 → 界面语言提供“跟随系统 / 简体中文 / English / 日本語”。默认跟随系统。手动选择立即刷新主窗口、菜单栏和当前弹窗，自动保存，无需重新启动，不重建会议或清空编辑中的输入。

## 匹配规则

按 `Locale.preferredLanguages` 顺序查找 `zh`、`en`、`ja`。识别地区变体和下划线格式；所有中文变体使用简体中文。列表中没有支持的语言时回退英文。应用重新激活或系统区域变化时刷新；macOS 本身要求重新启动才能生效的语言偏好，需遵循系统提示。

`interfaceLanguage` 为独立的 UserDefaults 应用偏好，不写入 `AppSettings` 或会议快照。切换显示语言不会改变识别语言、纪要语言、AWS profile、模型、音频缓存、原文、人物姓名或 AI 历史结果。

## 内容与界面

- 界面、实时／批量语音识别、纪要输出、全局词汇表均支持中文、日文、英文。识别另有中英混合和英日混合。界面切换不会隐式改变会议的识别和输出配置。
- 内置模板在界面显示翻译后的名称、要求与章节预览，原始定义及已保存快照不变。复制时产生独立的自定义模板，初始内容使用当前显示语言。
- 自定义模板、会议标题、原始转录、AI 正文、引用、人工编辑、词条、人物姓名及备注按原样显示。生成内容不会随着界面切换重新翻译。
- 应用诊断在显示时翻译，已保存诊断不改写；未识别的 AWS 或系统错误保留服务原文。
- 纪要导出按该版本保存的输出语言；已有正文和引用不因界面语言改变。
- macOS 自带应用菜单、文件选择器、权限提示和 Finder 名称由系统管理。包内提供 `zh-Hans/en/ja.lproj/InfoPlist.strings`，供系统选择；应用内手动切换不会修改全局 `AppleLanguages`。

## 开发

- `Sources/MeetingCore/Localization.swift`：语言解析、插值、只用于应用文案的查表、旧诊断的显示适配。
- `Sources/MeetingCore/Resources/Localization.json`：中文源文案键，对应 `en` 与 `ja` 译文，通过 SwiftPM 资源包分发。
- 界面常量使用 `L10n.tr("文案 \(参数)")`，插值与键分离，不把用户内容当作格式字符串。
- 应用拥有的枚举标签使用 `L10n.text`；持久化的系统诊断使用 `L10n.message`。不要将这两个方法应用到用户的正文、姓名或自定义模板。
- 所有 SwiftUI 页面观察应用的语言设置，并将 locale 显式传入文案和下拉选项，避免系统弹窗重设环境 locale 或缓存旧选项。不使用 `.id(language)` 重建页面，保留状态和未保存输入。
- `scripts/build-app.sh` 复制应用本地化文件与 SwiftPM 资源包；不要只复制可执行文件。

`LocalizationTests` 验证系统语言顺序、手动覆盖、缺省回退、全部译文与占位符一致性、插值原样保留、旧诊断翻译和模板／设置快照保护。单元测试不调用 AWS。

日文识别使用 `ja-JP`，中英混合使用 `zh-CN,en-US`，英日混合使用 `en-US,ja-JP`；实时传 `VocabularyNames`，批量按 `LanguageIdSettings` 匹配所选两种语言的词汇表。旧三语配置仅用于历史兼容，新录音不再提供该选项。日文词条支持汉字与假名；不同语言允许相同词条，各自维护和同步。词条仍受 AWS 对应语言的字符规则限制。

日文总结提示明确要求日文，内置模板章节与 Markdown/TXT 导出元数据采用日文，引用保持发言原文。日文的条件、建议和未确定决策会进入待确认事项。自定义模板标题保持用户填写内容，历史中英文版不会重写。
